OpenScreenShot предоставляет локальный MCP-сервер с одним инструментом: `capture_screenshot`. MCP-клиент может вызвать его с URL веб-страницы и получить изображение PNG. По умолчанию сервер запускает на вашем компьютере отдельный браузер без интерфейса, совместимый с Chrome; расширение для браузера не требуется.

## Добавьте сервер в MCP-клиент

Сначала установите Node.js, pnpm и браузер, совместимый с Chrome. Добавьте запись сервера в формате настроек вашего клиента. Клиенты, которые принимают объект `mcpServers`, могут использовать:

```json
{
  "mcpServers": {
    "openscreenshot": {
      "command": "pnpm",
      "args": ["dlx", "openscreenshot"]
    }
  }
}
```

Клиент должен находить `pnpm` в своём пути поиска исполняемых файлов. После сохранения настроек перезапустите клиент или перезагрузите его MCP-подключения. Сервер работает через stdio, поэтому клиент запускает локальный процесс, и вводить URL не нужно. Для клиентов, которые принимают только удалённые MCP URL, у OpenScreenShot Cloud есть удалённая точка подключения; она описана ниже.

Если Chrome установлен в необычном месте, передайте `CHROME_PATH` через настройки окружения клиента. Укажите полный путь к исполняемому файлу, а не к папке с приложением.

## Вызов capture_screenshot

Минимальные входные данные инструмента:

```json
{ "url": "https://example.com" }
```

Так получается снимок окна размером 1280 × 800 по умолчанию. Для воспроизводимого запроса задайте размер окна и параметр всей страницы явно:

```json
{
  "url": "https://example.com",
  "fullPage": true,
  "width": 1440,
  "height": 900
}
```

`width` принимает целые числа от 200 до 3840, а `height` — от 200 до 2160. Инструмент возвращает изображение MCP с типом MIME `image/png`. Аргумента для пути вывода у этого инструмента нет. Будет ли результат показан или сохранён, зависит от клиента; если вам сразу нужен файл с именем, используйте [CLI](/ru/blog/screenshot-cli/).

## Скройте данные до того, как изображение покинет инструмент

Добавьте объект `redact`, чтобы закрыть данные чёрными прямоугольниками на странице до съёмки. Клиент получает только изображение со скрытыми данными:

```json
{
  "url": "https://example.com",
  "redact": {
    "selectors": ["#account-menu"],
    "patterns": ["email", "phone", "secret"],
    "rects": [{ "x": 0, "y": 0, "width": 200, "height": 40 }]
  }
}
```

`selectors` закрывает каждый подходящий элемент вместе со всеми его потомками. `patterns` закрывает подходящий текст и значения полей форм: `email`, `phone` (от 9 до 15 цифр) и `secret` (типичные форматы ключей API и токенов, а также длинные хеши). `rects` закрывает прямоугольники в пикселях итогового изображения — для canvas, изображений и iframe с другого источника. Инструмент возвращает ошибку без изображения, если селектор ничего не находит, прямоугольник выходит за пределы изображения или страница сдвигает цель во время съёмки. Шаблоны могут пропустить текст, разбитый на несколько элементов или нарисованный на изображении.

## Рендеринг в OpenScreenShot Cloud

Добавьте `cloud: true`, чтобы рендерить страницу не в локальном Chrome, а в [OpenScreenShot Cloud](https://cloud.openscreenshot.app) — необязательном размещённом API для скриншотов:

```json
{ "url": "https://example.com", "fullPage": true, "cloud": true }
```

Режиму Cloud нужен API-ключ. Один раз выполните `pnpm dlx openscreenshot auth login`, чтобы сохранить ключ, или задайте `OPENSCREENSHOT_API_KEY` в настройках окружения сервера в клиенте. `redact` работает в обоих режимах. В режиме Cloud сервер Cloud рисует чёрные прямоугольники до того, как вернуть изображение.

Cloud также предоставляет удалённую точку подключения MCP через Streamable HTTP по адресу `https://cloud.openscreenshot.app/mcp` с тем же инструментом `capture_screenshot`. Передавайте API-ключ в заголовке `Authorization: Bearer <key>`. Используйте её с клиентами, которые принимают только удалённые MCP URL. Бесплатный план даёт 100 съёмок в месяц без карты; остальные планы перечислены на [странице цен](https://cloud.openscreenshot.app/pricing).

## Что агент видит и чего не видит

Съёмка начинается в новом браузере без интерфейса. Он не наследует cookie или сеанс входа из вашего обычного окна Chrome. Поэтому страница, требующая входа, может дать экран входа. Текущий инструмент не предоставляет шаги входа, подстановку cookie, ожидание селекторов или интерактивные клики.

Прежде чем делать выводы, попросите агента описать, что на самом деле видно на полученном изображении. Скриншот помогает проверить макет, отступы и видимые ошибки; он не может подтвердить, что форма отправляется правильно или что работает навигация с клавиатуры.

## Куда попадает скриншот?

По умолчанию скриншот создаётся локально и возвращается MCP-клиенту. Если клиент использует размещённую модель, он может передать полученное изображение поставщику модели согласно своим настройкам. Локальная съёмка не означает, что весь разговор с агентом остаётся на устройстве. Используйте `redact` для данных, которые не должны попасть к поставщику. С `cloud: true` URL и параметры уходят в OpenScreenShot Cloud, а страница рендерится на его серверах; см. [политику конфиденциальности Cloud](https://cloud.openscreenshot.app/privacy).

Для автоматической съёмки с предсказуемыми размерами см. [скриншоты для CI](/ru/blog/screenshots-for-ci/). [Навык агента для съёмки](/skills/capture-screenshot.md) и [исходный код сервера](https://github.com/pghqdev/OpenScreenShot/blob/main/mcp/src/serve.ts) содержат инструкции для машин и определение инструмента. Сервер также есть в каталоге [Glama](https://glama.ai/mcp/servers/PGHQdev/OpenScreenShot).
